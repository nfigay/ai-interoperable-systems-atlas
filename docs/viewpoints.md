# Architectural viewpoints

The atlas uses **multiple** viewpoints, not a single AI- or SE-centric hierarchy.

1. **SE → AI:** integrate and verify AI components within systems of interest, including non-software systems.
2. **AI → SE:** use AI for requirements, engineering models, simulation and verification activities.
3. **Enterprise architecture:** capabilities, dependencies, governance, costs and portfolio evolution, using ArchiMate where appropriate.
4. **Knowledge and semantics:** ontologies, graphs, formal inference, heterogeneous information and semantic mappings.
5. **AI science:** algorithms, learned models, reasoning, planning, multi-agent systems, evaluations.
6. **Distributed systems:** browser, services, processes, cloud, APIs, middleware, identity, protocols and service mediation.

## Representation choices
- **ArchiMate:** enterprise architectural elements and relationships.
- **SysML/UML:** structure, requirements and behavior.
- **BPMN and WfMC:** process definitions, workflow enactment, activity execution.
- **RDF/OWL/SHACL:** representations, ontological entailment, validation as relevant.
- **API/OpenAPI/MCP:** invocation contracts, capability interfaces and protocols.

No one notation is assumed to subsume the others. Architecture views should include model boundaries, stakeholder concerns and source traceability.
