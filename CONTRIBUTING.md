# Editorial workflow

1. Open a GitHub Issue for a disputed definition, missing reference or new atlas region.
2. Edit an entry in its source Markdown/JSON; retain a stable identifier.
3. State type (N/S/E/P/U), scope, source URL, and uncertainty.
4. Use Pull Requests for technical review and explicit acceptance.
5. Treat diagrams as views: retain their source format and references to concepts.
6. Do not claim exact quotations or detailed standard requirements without checking the normative text.
7. Record date and version of vendor behavior/specifications.
8. Separate personal/internal content from what can be published publicly.
